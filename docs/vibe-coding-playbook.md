# 海霸王員工特約商店｜Vibe Coding 實作手冊

這份手冊記錄如何用自然語言和 Codex 一起開發、驗收與維護員工特約商店網站。適合接手網站的同仁、HR 和福委會使用。優惠資料以網站的資料維護流程為準，設計與程式變更則走 GitHub。

## 常用的 Prompt 技巧

| 技巧 | 怎麼寫 | 本案用法 |
| --- | --- | --- |
| 說明員工的使用情境 | 寫清楚誰、在哪裡、要完成什麼 | 「員工在櫃檯結帳前用手機查優惠，先讓搜尋與門市資訊好找。」 |
| 指定畫面和修改範圍 | 說明是哪個頁面、元件、尺寸，必要時附截圖 | 「手機版 768px 以下，把 Hero 改為約 52vh，分類捷徑緊接在下方。」 |
| 把定案寫成可驗收的規格 | 色碼、文案、對齊、位置和互動都用具體值 | 「桌機右側文字靠左，分類提示在首屏底部中央，距底部 28px。」 |
| 附一筆輸入和預期結果 | 用真實的資料形狀描述問題，再寫出正確結果 | 「同門市 ID 有員工與主管兩筆。選『全部』時顯示一張卡、兩筆優惠。」 |
| 指定參考素材的用途 | 交代檔名、裁切、透明背景和需要保留的細節 | 「使用附件的透明 PNG，保留原本的中文字形與紅印，分別用於導覽列和分享縮圖。」 |
| 把驗收寫進任務 | 指定要測的情境與可觀察結果 | 「部署後核對 390px 和桌機畫面，確認首頁、返回鍵和分類連結。」 |

可直接複製這個格式，再填入本次要改的內容：

```text
情境：員工從手機首頁進站，想快速找到可用優惠。
範圍：首頁 Hero 和分類捷徑。
畫面：手機 768px 以下，Hero 約 52vh，分類捷徑緊接下方。
保留：桌機構圖、原始背景照片、查詢入口和瀏覽器返回行為。
驗收：在 390 × 844px 檢查首屏是否看得到按鈕和分類卡，且無水平溢出。
交付：部署後提供網站連結與實測結果。
```

把「去 AI 味」拆成可以檢查的條件，比只要求「有質感」容易取得一致結果。這次用細邊框、票券虛線、精簡文案、清楚的資訊層次與實際品牌素材來定義風格。設計有新定案時，直接寫清楚哪些頁面要套用，尤其是首頁和查詢頁採用不同佈局的情況。

## 踩雷紀錄

| 發生過的問題 | 原因與處理 | 驗收方式 |
| --- | --- | --- |
| GitHub 已有程式，Pages 還沒上線 | 第一次要在 Settings → Pages 設定從 `main` 根目錄發布。後續提交後查看 Pages 部署結果。 | 開啟正式網址，確認看到該次更新。 |
| 頁面更新了，但樣式或按鈕仍是舊版 | HTML、CSS、JS 和資料可能各自被快取。修改介面或資料時，同步更新受影響檔案的引用版本。 | 確認正式頁面載入正確版本，並操作本次修改的功能。 |
| 職級選單的紅色焦點框只包到一半 | 焦點框畫在複合欄位的一部分。將搜尋、職級、地區統一成相同高度與完整焦點樣式。 | 用 Tab 逐一聚焦，檢查欄位四邊及窄螢幕排列。 |
| 同一家店算成兩間，或「全部」只顯示一種優惠 | 不同職級用了不同門市 ID，且舊渲染邏輯每店只取一筆。改用相同門市 ID，選「全部」時一店一卡列出各筆優惠。 | 交接時的資料共 47 筆優惠、26 間門市。21 間各有員工和主管優惠，另 5 間是全職級適用。 |
| 舊 CSV 的分類或職級值驗證失敗 | CSV 驗證與前端分類曾不同步。目前正式類別為餐飲美食、旅遊住宿、生活購物。舊休閒與醫療類別先改成生活購物，職級用員工、主管或留空。 | 匯入前以最新版範本核對欄名與選項，測一筆有效資料和一筆不合規資料。 |
| 原本的 Logo 有灰邊，重新生成後紅印走樣 | 品牌標誌要保留原始字形和印記。最後改用使用者提供的透明 PNG，分享圖用同一份圖檔排成 1200 × 630。 | 對照原始紅印、查看導覽列背景上的邊緣，並核對分享圖網址。 |
| 分享預覽仍顯示舊縮圖 | 分享預覽由各平台抓取，可能有平台快取。更新 `og:image` 時採用新資產檔名，確認分享網址與圖片均可公開讀取。 | 先確認正式 HTML 的 OG 標籤和圖片，再用需要的通訊平台檢查預覽。 |
| 以為選職級或輸入維護密碼就能保護優惠 | 公開 Pages 會提供前端檔案。職級是篩選條件，維護密碼是前端介面限制。本案移除公開資料與 CSV 中的優惠碼欄位。 | 檢查發布內容可否公開。若有需要保密的資料，需由有身分驗證與授權的系統提供。 |

## 工具設定與日常維護

| 工具／檔案 | 用途與設定 |
| --- | --- |
| Codex | 讀取最新 GitHub 版本，按需求修改，再用桌機與手機尺寸核對。進行後續迭代前先確認同仁是否剛上傳新資料。 |
| GitHub Pages | 靜態 HTML、CSS、JavaScript。以 `main` 根目錄部署，使用 `.nojekyll`，資產用相對路徑。部署完成後再檢查正式網址。 |
| `index.html`、`style.css`、`script.js` | 首頁、搜尋頁和顯示邏輯。首頁與 `#search` 切換使用瀏覽器歷史，搜尋內的篩選更新目前歷史項目，避免按一次返回只退回上一個篩選。 |
| `admin.html`、`admin.js`、`data.js` | 維護頁在瀏覽器內匯入、驗證和下載。Excel 另存 CSV UTF-8（逗號分隔），上限 5 MB。下載新 `data.js` 後提交到 GitHub，網站才會更新。 |
| Google Maps、Google Forms、Open Graph | 地圖用門市地址或 Place ID 開啟 Google Maps，無須 API Key。許願池從頁尾連到 Google Forms，回覆權限在 Forms 管理。分享標題、摘要與絕對 HTTPS 圖片網址放在 `index.html` 的 OG 標籤。 |

更新優惠時，可先從維護頁匯出最新版 CSV，再用 Excel 編輯。電話、門市 ID 和日期建議設為文字欄，避免前導零和格式改變。同一門市的各職級沿用同一 ID，同一 ID 和職級只能有一筆。以整組門市列為單位排序，可以維持切換職級時的相對順序。發布前核對「全部／員工／主管」、官網與地圖連結、門市數和範例資料標記。完整欄名與限制以 [CSV 匯入程式](../admin.js) 為準。

## 網站風格的定案脈絡

1. **查詢先行**。初版使用玫瑰紅與票券插圖，之後壓低 Hero 的高度與裝飾，讓搜尋和門市卡片更接近結帳現場的使用情境。保留卡片網格與票券虛線。
2. **首頁與搜尋頁分工**。品牌首頁提供「立即查詢」與分類捷徑，搜尋頁集中搜尋框、職級、地區、類別與卡片。桌機首頁保有品牌構圖，手機首屏同時露出主視覺和分類卡。
3. **從和紙格紋到自然光影**。早期試過幾何線條、淡漸層和襯線主標，後來採用窗框與龜背芋葉影的照片。桌機左光影、右文字，右側文字靠左，導覽列透明。手機保留置中，Hero 約 52vh，照片焦點為 `20% 25%`，以柔和遮罩維持文字對比。
4. **用品牌色和字體建立資訊層次**。定案採暖灰米色 `#F5F2EE`、白色卡片、深炭灰 `#1F1C1B` 和海霸王暗紅 `#8C1D24`。使用 Inter 搭配 Noto Sans TC，主標為無襯線黑體，日期使用等寬數字。集團品牌在卡片右上角用暗紅底白字標示。
5. **首頁定稿**。主標為「集團特約優惠」，副標為「餐飲、星級旅宿與精選生活品牌禮遇」，主行動為「立即查詢」。桌機的「依類別瀏覽」置於首屏底部，手機直接銜接分類。導覽列使用原始透明品牌標誌，頁尾以文字連結並列「許願池」與「資料維護」。

交接核對的程式版本為 `2252c8d`。日後若品牌設計或匯入規則改版，請同步更新本手冊對應段落，並以最新網站與程式實測為準。
